# Software Architecture Review

## When to activate

Use when describing architecture ownership or multi-component designs.

## Procedure

1. Define purpose, constraints and system boundaries.
2. Sketch data and control flow from known evidence.
3. Review major components and interfaces.
4. Check stated tradeoffs, failure modes and alternative choices.
5. Determine candidate's actual design contribution.
6. Flag unsupported architecture terminology.

## Expected output

An architecture credibility analysis.

## Domain-specific caution

Do not assume ownership from a diagram of a system the candidate used.
