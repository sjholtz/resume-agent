# Candidate Context Interviewing

Activate for general profile discovery or a company-triggered clarification routed by the Orchestrator.

1. Offer the candidate an optional interview on earlier work outside tech, practical product use, hobbies, volunteering, communities and customer experience. Ask open questions; do not presuppose an answer or solicit sensitive traits.
2. Distinguish the candidate's actual relationship to a company/product/project from the company's public descriptions. Record direct use versus ownership versus employment distinctly; never infer AI/software implementation from product use.
3. Locate existing EXP-/PROJECT-/EDU-/EVID- entries; link rather than duplicating. A previous paid job remains EXP-, not merely a hobby entry.
4. Propose a `CTX-NNNN.json` under the configured candidate root `context/`, following `docs/CANDIDATE_CONTEXT.md`. Default to `disclosure_preference: ask_per_application`. Preserve unsure facts as tentative, or use a nonblocking FUP.
5. Submit the exact write through existing candidate-content and tool-operation HITL gates. A candidate declining to answer or declining future disclosure is not permission to write or publish.
6. Tell the Orchestrator which new facts are recorded, which still need confirmation, and that use in a particular application needs its own explicit authorization.

Do not edit application files or bypass approvals. `CTX-` does not imply `SKILL-`, `COMP-`, `EXP-` or an employer's endorsement.
